# 开源大梳理 — 需求定稿（唯一事实源）

> 本文档是"开源大梳理"的唯一权威需求。所有实现、技能、数据、文案必须服从本文档。
> 旧的图谱目录（data/domains 501 节点、graph/edges.yaml 658 边、dist/v1）已废弃，不再是需求，不迁移、不继续维护。
> 最后更新：2026-08-13

---

## 0. 一句话定位

一个像小说/影视分类站一样的开源项目发现与推广平台：
- 每个开源项目，由智能体完整看一遍后，写出一篇有观点、可核验的介绍（不是冷冰冰的字段清单）。
- 同时服务真人和智能体两种使用者，共享同一份数据。
- 靠固定、不挡内容、不乱动的广告位赚钱。

## 1. 两种形态，一份数据

| 形态 | 谁用 | 长什么样 | 能力 |
|---|---|---|---|
| 真人网页 | 人类 | 小说/影视分类站：分类发现→项目卡片快速判断→详情页深读→作者聚合 | 搜索、筛选缩小范围、读介绍 |
| 智能体入口 | 智能体（含企业智能体） | 机器可读：REST API + MCP + 快照文件 | 搜索、挑库、读介绍、上传/修改内容、提交变化报告 |

同一份数据：网页、API、MCP 从同一个数据库（D1）读，不做多份副本。

## 2. 每个项目的核心 = 一篇介绍

项目主体不是字段清单，是一篇看完项目后写成的介绍。

固定栏目（顺序不可变）：
1. 项目概览 2. 问题与定位 3. 背景与历史 4. 人物与组织 5. 设计理念
6. 架构与技术 7. 核心能力 8. 安装与使用 9. 限制与风险 10. 维护与发布
11. 生态与互操作 12. 替代与选择 13. 社区与渠道 14. 编辑部评估（介绍的灵魂）

卡片（快速判断）额外必须有：名称+中文名、≤80字客观摘要、use_when、avoid_when、分类、语言、许可证、维护状态、作者、核验状态。

禁止：字段堆砌；写"最好/最强"等无证据营销词；用 star 代替质量判断。

## 3. 语言切换（整站级，不混排）

- 一个语言切换点，切换整个站点：界面 + 介绍一起变。
- 硬规则：中文站全中文、英文站全英文；英文内容出现在中文站必须带中文名（chinese_name）。
- chinese_name 是发布硬门槛：缺中文名的项目在中文站不能发布。
- 多语言以后加 = 每语言一份翻译，版本+哈希管理，不改结构。

## 4. 作家助手（内部编辑控制台）

- 内部后台 Studio，智能体用独立凭证 + 最小权限 scope 进入。
- scope：draft:create / draft:update / evidence:add / review:approve / publish / ad:create / ad:update。
- 智能体能：上传新项目介绍、修改已有介绍、上传/修改广告内容。
- 权限轻松可控：独立身份、可撤销、可审计、不用管理员密钥。
- 流程：草稿→审核→发布；审核不审自己；发布只出新修订不覆盖。

## 5. 广告（固定、不乱动、不挡内容）

### 5.1 坑位与素材分开
坑位写死在布局里，比例固定；接广告只往坑里填内容，坑纹丝不动。
比例（用户决定）：宽 16 份 → 内容占 13，剩 3 拆成几块广告位放左右两边。

### 5.2 广告位清单（固定坑位）
- 左轨 / 右轨（桌面宽屏）：竖向堆叠多个固定坑
- 顶部横幅：分类条下、内容上方
- 内容末尾：介绍看完后
- 禁用：内容中段、弹窗、底部固定条（会挡内容）
- 窄屏（<1200px）自动收起左右轨，只留顶部横幅+末尾。

### 5.3 广告怎么接
- 真人广告（如 Google AdSense）：贴联盟给的 JS 代码到坑位，Google 脚本自动渲染。
- 智能体广告（自营赞助）：需要自己的数据实体（广告主、落地页、有效期、审核状态），存 D1，走审核。
- 隔离硬规则：organic_results 与 sponsored_results 分开；付费不改自然排序、不隐藏竞争项目、不改事实。

## 6. 搜索与筛选（只留一个搜索入口）

- 全局只留一个搜索框（顶栏）。
- 目录页只做分类+筛选（领域 chips + 下拉），不再放第二个搜索框。
- 心智：搜索一次到位 → 筛选缩小 → 点进详情读介绍。
- 智能体走 API/MCP 的 search_projects / search_creators / find_similar_projects。

## 7. 旧数据废弃策略（明确）

- data/domains（501 节点）、graph/edges.yaml（658 边）、dist/v1、control 旧 schema：全部冻结废弃，不迁移、不继续维护。
- 新数据从"智能体看完项目写介绍"新流程重新积累。
- 将来导入旧数据只作 legacy_imported 参考，缺失栏目标 unknown。

## 9. 采集技能（Skill）——固定流程

> 后续做成的"技能"：智能体安装后按此固定流程走。

### 9.1 收集什么类型的信息
1. 稳定身份（规范 URL、platform_repository_id、默认分支、fork/镜像/改名/转移）
2. 时间证据（created_at/updated_at/pushed_at/observed_at/每个 release 的 released_at）
3. 名称与中文名（原始名、中文名、别名、历史名）
4. 一句话客观定义（≤80字）
5. 人物与组织（创建者/owner/维护者/组织/基金会，带证据）
6. 技术栈（语言、框架、运行时、协议、交付方式、安装、最小用法）
7. 许可证（SPDX、按版本生效范围、附加条款、证据 URL）
8. 生命周期（稳定/LTS/预发布/EOL、维护状态、最近活动）
9. 中文支持（界面/文档/社区）
10. use_when / avoid_when
11. 关系（替代/依赖/配套/生态）
12. 证据（每条事实带 evidence URL）

### 9.2 发到哪个站、点什么按钮、传到哪个位置
1. 打开 GitHub 读公开信息（只用公开 API/README/LICENSE/Release，不 clone 全量、不执行代码）
2. 到平台进入【作家助手 Studio】
3. 点【新建项目】→ 查重（返回 已有/改名/疑似重复/新仓库）→ 新仓库签发 creation_ticket
4. 按 9.1 清单逐项填写（固定栏目 + 卡片 + 证据）
5. 点【预览】自查
6. 点【提交审核】→ in_review
7. 独立复核审核 → approved
8. 点【发布】→ 新修订，公开可见

硬规则：不在本地积累外部仓库副本；用稳定 ID 去重；证据不足填 unknown 不编造；推断标 inferred；智能体广告走 ad:create → 审核 → sponsored_results。
